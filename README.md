# WeekLog 使用说明（Git 提交自动写入 SharePoint 周报）

## 一、运行环境

1. Windows 10 / 11。
2. 桌面版 Excel（Microsoft 365 或 Excel 2016 及以上），并已登录公司账号。
3. Python 3.10 及以上；安装时勾选“Add Python to PATH”。
4. 第一次启动需要联网安装依赖。

## 二、第一次启动

1. 解压整个文件夹到本地目录（不要放在压缩包里直接运行）。
2. 双击 `start.bat`。
3. 黑色窗口会检查依赖；缺少时自动 `pip install`，第一次大约 1~3 分钟。
4. 启动后会自动打开浏览器：<http://localhost:5000>。
   如果没有自动打开，手动在浏览器输入这个地址。
5. 不要关闭黑色命令行窗口；关闭窗口 = 停止服务。
6. 如果提示端口 5000 被占用：关闭占用该端口的程序，或重启电脑后再试。

## 三、设置（第一次使用按顺序做，最后一定要点“保存设置”）

进入页面顶部“设置”。

### 1. SharePoint 目标

#### 1) 在线文档链接

**推荐：由程序打开文档链接（全自动，已实测）**

- 必须填“直接文件路径”，形如：
  `https://你的租户.sharepoint.com/sites/站点名/Shared Documents/文件夹/周报.xlsx`
- 不要填 `doc.aspx?...` 查看器链接，否则 Excel 会把它当成网页打开。
- 获取直接路径的常见方法：
  1. 在 SharePoint 文档库找到文件，点“...”->“详细信息”，查看路径；
  2. 把文档库同步到 OneDrive，直接用本地 xlsx 路径（程序也支持本地路径，OneDrive 会自动上传）；
  3. 在浏览器中打开文件所在文档库，地址栏里以 `.xlsx` 结尾的地址就是直接路径。

**备用：附着到已打开的 Excel（效果不稳定，不推荐）**

- 可以粘贴 SharePoint 里复制出来的链接，包括 `doc.aspx` 查看器链接。
- 程序只用它来识别文件名，不会去打开这个链接。
- 最稳妥的做法：只打开目标周报一个工作簿，再点检测。
- 实测附着效果不佳，请优先使用上面的“由程序打开”。

#### 2) 写入方式

- **由程序打开文档链接（推荐）**：
  程序启动隐藏 Excel 打开上面的直接路径，写入后保存并关闭。
  写入前必须关闭 Excel 中已经打开的该文件。
- **附着到已打开的 Excel（仅备用）**：
  先在桌面版 Excel 中打开周报，程序找到它后写入并保存。
  实测效果不稳定，除非无法使用打开模式，否则不推荐。

#### 3) 其他

- 工作表名称：留空 = 自动；识别不到时填实际 sheet 名。
- 表头行：`0` = 自动；识别不到时填表头所在行号（例如 `1`）。
- 默认演练模式：建议保持开启，第一次先演练。

#### 4) 写入目标

- 写入现有工作表：写到你指定的现有 sheet（日报/汇总）。
- 每周新建周报汇总 sheet：复制模板 sheet，按起始日期新建一个 sheet。
- 日报 + 每周新建周报汇总 sheet（两者都写）：先写日报，再新建周报汇总。
  详细操作见第九节。

### 2. Git 数据源

1. 作者过滤：Git 提交作者名，支持模糊匹配，例如 `your.name`；留空统计所有人。
2. 执行人显示名：写入周报“姓名 / 执行人”列；留空则使用上面的作者过滤值。
3. 每周起始日：周一或周日（“按周”模式使用）。
4. 仓库路径：每行一个本地 Git 仓库目录，例如 `D:\code\project`。
5. 填完点“检测仓库”，每个仓库显示“正常”才可用。

### 3. 工作表与表头（模板检查）

如果不知道 sheet 名或表头行：

1. 从 SharePoint 下载一份周报副本到本地。
2. 设置页“模板检查”->“上传模板”，或直接填本地模板路径。
3. 点“解析本地模板”。
4. 查看识别到的工作表、表头行、字段列。
5. 点“应用此工作表与表头”。
6. 回到页面底部点“保存设置”。

这一步只解析本地文件，不会修改 SharePoint 原文件。

### 4. 字段映射

1. 程序按表头名称自动匹配列，默认已包含常见名称。
2. 如果你们的表头不一样（例如用“工作内容”而不是“任务描述”），
   在对应字段里补别名，用逗号分隔。
3. 匹配不到的字段会跳过，不影响其他列。

### 5. 写入细节

#### 1) 汇总粒度

- 按 Ticket + 日期（默认，适合日报）：
  - 同一天不同 Ticket 写成多行；
  - 同一 Ticket 不同天分成多行；
  - 同一 Ticket 同一天的多条提交合并成一行。
- 按 Ticket（适合周报汇总表）：
  - 整个时间范围一个 Ticket 一行。
- 周报汇总模式固定“按 Ticket”，不受这里影响。
- 日报 + 周报汇总模式：日报按 Ticket + 日期，周报汇总按 Ticket。

#### 2) 日期写入方式

仅“按 Ticket”粒度生效；“按 Ticket + 日期”直接写提交当天。

周报汇总 sheet 没有日期列，此项不生效。
日报 + 周报汇总：日报按提交当天写；周报汇总无日期列。

#### 3) 其他选项

- 复用未填充的日期行：默认开启。
  程序优先从表格末尾的空日期行开始写；运行日志会显示“从第几行开始”。
- 复用上一行格式：复制边框、字体、底色。
- 插入到页脚之前：遇到“合计 / 总计 / 小计”行时插在它前面。
- 忽略 Merge 提交：默认开启。
- 描述最大长度：AI 或拼接描述的截断长度。

### 6. AI 改写（可选）

1. Base URL：`https://api路径`
2. 模型：`deepseek-flash`
3. API Key：`xxx`
4. 启用 AI 改写：打开
5. 系统提示词：默认已写好，可按团队口径修改
6. 先点“保存设置”，再点“测试 AI 连接”，显示连接成功即可
7. AI 失败不会影响主流程：会自动使用原始 Git 提交说明

### 7. 保存设置

所有修改完成后必须点“保存设置”，否则不生效。

## 四、日常使用流程（从采集到写入）

1. 打开首页。
2. 选择时间范围：
   - 按周：用左右箭头切换周，点“回到本周”可快速回到当前周。
   - 自定义：切到“自定义”，选择开始和结束日期（最多 366 天）。
3. 点“采集提交”：
   - 程序读取配置的仓库，按作者和日期过滤；
   - 按 Ticket + 日期汇总；
   - 启用 AI 时会调用 AI 改写描述，可能需要几十秒。
4. 检查汇总预览：
   - 每行是一个 Ticket 在一天的工作；
   - 可以直接编辑：任务描述、工时、进度、备注；
   - 有 AI 标记表示描述由 AI 生成；
   - 可点“AI 重写描述”重新生成；
   - 展开“Git 提交明细”可核对原始提交。
5. 点“写入周报”：
   - 确认弹窗会显示时间范围、写入行数、执行人、工作表、日期、写入方式；
   - 默认勾选“演练模式”：只分析表头和插入位置，不保存；
     建议第一次先演练，确认工作表和第几行正确；
   - 确认无误后，取消勾选“演练模式”；
   - 推荐“由程序打开文档链接”模式，程序会自动打开、写入、保存、关闭；
   - 只有使用附着模式时，弹窗里才需要显示“已找到工作簿”；
     没找到就打开 Excel 后点“重新检测”；
   - 点“开始”。
6. 等待结果：
   - 成功：显示工作表和第几行，Excel 中可直接查看；
   - 失败：点“查看记录”，看日志和错误信息。
7. 查看填充记录：
   - “填充记录”页列出每次运行；
   - 可下载“写入前快照”和“审计表”；
   - 详情页有汇总行、Git 明细、运行日志；
   - 失败可以点“重试”。

## 五、两种写入方式怎么选

**优先使用方式 A；方式 B 仅在无法使用 A 时临时备用。**

### 方式 A：由程序打开文档链接（推荐，已实测）

1. 设置里填“直接文件路径”（不是 `doc.aspx` 查看器链接）。
2. 写入前关闭 Excel 中已经打开的该文件。
3. 程序会隐藏打开、写入、保存、关闭。
4. 如果提示“文件被占用”或“只读”：
   - 关闭 Excel 中的该文件；
   - 检查 SharePoint 编辑权限和文件锁定。

### 方式 B：附着到已打开的 Excel（备用，效果不稳定）

1. 在 SharePoint 点“在桌面应用中打开”，让周报在 Excel 桌面版打开。
2. 设置里选“附着到已打开的 Excel”，链接粘贴 SharePoint 复制的链接即可。
3. 首页写入时，弹窗会检测工作簿。
4. 如果提示“未检测到 Excel”：
   - 不要用 SharePoint 网页里的预览窗口；
   - 从开始菜单正常打开 Excel，再“文件 -> 打开”打开周报；
   - 回到程序点“重新检测”。
5. 写入成功后，Excel 中的工作簿会保持打开，可直接检查。
6. 注意：附着模式实测效果不佳，能使用方式 A 时不要用方式 B。

## 六、常见问题

1. 启动报 “'xxx' 不是内部或外部命令”：
   - 确认 `start.bat` 没有被记事本另存为其他编码；
   - 确认 Python 已安装，并且安装时勾选了 Add Python to PATH。
2. 浏览器打不开：
   - 看黑色命令行窗口是否报错；
   - 检查 5000 端口是否被占用。
3. 采集到 0 条提交：
   - 检查作者名、仓库路径、时间范围；
   - 确认本地仓库已经拉取到最新提交（程序读取所有分支和远程）。
4. 表头识别失败：
   - 在设置里填工作表名和表头行；
   - 用“模板检查”校准；
   - 检查字段别名是否覆盖了实际表头。
5. 写入失败“文件被占用”：
   - 关闭 Excel 中打开的该文件；
   - 推荐使用“由程序打开文档链接”，不要依赖附着模式。
6. 写入失败“只读”：
   - 检查 SharePoint 编辑权限；
   - 检查文件是否被其他人锁定。
7. 附着模式“未检测到 Excel”：
   - 优先改用“由程序打开文档链接”；
   - 如必须附着：用正常桌面 Excel 打开周报，不要用网页预览窗口。
8. AI 失败：
   - 检查 Base URL、API Key、模型；
   - 可先关闭 AI 改写，程序会用原始 Git 提交说明。
9. 写入后日期或行数不对：
   - 先跑演练，看日志里的“最后数据行 / 最后使用行 / 从第几行开始”；
   - 用“填充记录”里的写入前快照对比或恢复。
10. 表格里多出空日期行：
    - 程序会复用空日期行；如果空行比数据多，多余行会保留；
    - 手动删除多余空行即可。

## 七、文件与数据说明

| 路径 | 说明 |
| --- | --- |
| `backend\data\app.db` | 配置和填充历史（含 API Key，不要外发） |
| `backend\data\snapshots\` | 每次写入前的快照 |
| `backend\data\audit\` | 每次运行的审计表 |
| `backend\data\logs\` | 每次运行的日志 |
| `samples\` | 本地模板副本（可选） |

分享给别人时，不要带 `backend\data` 和 `samples` 里的真实数据。
当前分享包已经清理，首次运行会自动生成新的数据库。

## 八、安全提醒

1. API Key 保存在本地 SQLite，不要分享 `backend\data` 目录。
2. 快照和审计表包含工作内容，请按公司规定保管。
3. 正式写入前先演练，确认快照已生成。
4. 写入前确认目标工作表、表头行、起始行正确。

## 九、每周新建周报汇总 sheet（新增）

适合每周生成一份新的汇总表，例如“周报汇总 10.19”。
如果希望日报也写，见本节第 5 点。

### 1. 设置

1. 写入目标选“每周新建周报汇总 sheet”。
2. 模板工作表：
   - 留空：程序自动找最后一个名称含“周报汇总”的 sheet 作为模板。
   - 也可以明确填写，例如：`周报汇总 9.7`
3. 新 sheet 前缀：默认“周报汇总”。
   新 sheet 名 = 前缀 + 起始日期（月.日），例如 `周报汇总 10.19`。
4. 同周重复写入时覆盖：
   - 开启（默认）：同一周再次写入时，清空已生成 sheet 的数据后重写。
   - 关闭：在名称后加 `(2)`、`(3)`，保留旧 sheet。
5. 表头行：`0` = 自动；模板表头在第 1 行时也可以填 `1`。
6. 保存设置。

### 2. 模板要求

- 模板 sheet 的表头行要有这些列（名称可不同，用字段映射补别名）：
  `执行人 / 完成事项 / Ticket/需求编号 / 工时 / 状态 / 进度`
- 程序只复制模板，不会修改模板本身。
- 模板里的数据行会被清空后写入新数据；格式、列宽、表头会保留。

### 3. 日常写入

1. 首页选按周或自定义时间范围。
2. 采集提交。周报汇总模式固定“按 Ticket”汇总：
   整个时间范围一个 Ticket 一行。
3. 检查预览：
   - 任务描述（完成事项）可编辑；
   - 工时、状态、进度可先在预览里填，也可以写入后在 Excel 里补；
   - 启用 AI 时，描述会按 Ticket 自动改写。
4. 点“写入周报”：
   - 确认弹窗会显示“新工作表”名称和“模板”；
   - 先演练，确认名称和第 2 行开始写入；
   - 取消演练后正式写入。
5. 写入成功后，Excel 中会多出一个 sheet，例如“周报汇总 10.19”。
6. 同周重复写入默认覆盖该 sheet；如果想保留旧版本，关闭“同周重复写入时覆盖”。

### 4. 注意

- 新 sheet 名称不能和模板相同；如果相同，程序会报错，请改前缀或模板。
- 模板 sheet 名称留空时，程序会选最后一个含“周报汇总”的 sheet；
  如果自动选错，请手动填模板名称。
- 周报汇总 sheet 没有日期列，所以“日期写入方式”不生效。
- 汇总粒度固定按 Ticket，不能选“按 Ticket + 日期”。
- 模板里的旧数据行会被清空；写入前快照可在“填充记录”里下载。

### 5. 日报 + 周报汇总（两者都写）

- 写入目标选“日报 + 每周新建周报汇总 sheet（两者都写）”。
- 预览显示日报行（Ticket + 日期）；写入时先写日报，再新建周报汇总。
- 周报汇总按 Ticket 生成：
  - 工时 = 该 Ticket 日报工时合计；
  - 状态/进度 = 该 Ticket 日报最后一条非空值；
  - 描述 = AI 改写（关闭 AI 时用提交说明拼接）。
- 审计表会同时包含“填充记录”（日报）和“周报汇总”两个 sheet。
- 同一周重跑：周报汇总默认覆盖；日报会继续追加，可能重复。
  建议先看“填充记录”里的快照，必要时恢复后再跑。
